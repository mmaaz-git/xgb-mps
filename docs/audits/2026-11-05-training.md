# Frozen training/prediction caller audit

Implementation: `382f78ce867bfa248cd85088c70322edca8805fb`; import: `22a84e0538e8c8db8d517c610b393bd5799a05d5`. This is a static audit of 15 assigned families, with **68 logical operation rows: 43 implemented, 13 missing, 10 source-host, 2 platform adaptations**. The JSON assigns all **203 candidate lexical lines** to reviewed operations: 103 consumers, 97 support sites, 3 non-operation sites; none unassigned. Those lexical counts are bookkeeping, not a parity percentage or semantic completeness proof.

The audit read the producers, storage boundaries and actual consumers, not just interfaces. Existing named tests and historical M3 records are linked per row; no new build, test suite or heavy job was run. No NVIDIA execution or cross-Apple-hardware result is claimed. CUDA roots match the import except two `value_gpair_.Empty()` checks changed to `Shape(1)` checks in `updater_gpu_hist.cuh` (frozen lines 236 and 357), affecting empty-worker value-gradient presence. The quarantined weight draft is excluded.

PORT-9 has a deterministic source witness: with a vector tree, `subsample=1`, leaf node `0` and a row whose target Hessians are `[0,0]`, CUDA `SamplingInfo::kNone` returns probability one and `FinalizePosition` writes `0` (`updater_gpu_hist.cuh:625-635`, `sampler.cuh:51-69`). Metal's `xgb_leaf_positions` writes `~0`, or `-1` (`metal_histogram.metal:658-664`). Existing updater fixtures use Hessians at least one (`tests/metal_training_state_api.cc:255-256`). This is an open correctness defect, not a tolerated numerical divergence. No runtime reproduction was needed or claimed.

Several host boundaries are valid by direct source comparison: CUDA scalar split entries and scalar categories are published to host; scalar root sums are returned to host; quantizer global bounds/coefficient construction are host; coordinate selectors and scalar model deltas are host; SHAP model compression/covers are host; final refitted leaves explicitly use `out_weight.ConstHostSpan()` before `SetLeaves` (`updater_gpu_hist.cuh:406`). None are counted as missing. Refitted leaf code has a potential bound gather, but the public reduced-gradient path rejects monotonic constraints (`gbtree.cc:250-254`); PORT-8 counts only active scalar/vector split consumers. Ordinary host launch descriptors alone are not treated as missing work. PORT-10 excludes categorical values: OHE cut lookup/category conversion/bit setting already execute on GPU (`metal_histogram.metal:6971-6988`), scalar categorical expansion ignores `split_value`, and vector categorical expansion writes `DftBadValue` in common host code (`multi_target_tree_model.cc:237`).

`GPUDartPredictInc` and `GPUDartInplacePredictInc` have no production callsites at this revision. Their lexical launches are non-operation entries linked to the actual weighted-prediction operation, which runs through tree weights in the predictor. Likewise iterator/type declarations and scratch-size queries support their owning consumers; they are not independent missing kernels.

Core quantized histogram accumulation/subtraction, scalar/vector split arithmetic, category bit assembly, partitioning, value-gradient sampling replay, exact leaf sums/weights, coordinate descent, traversal and SHAP have Metal compute paths. The independent missing rows explain why those kernels and passing arithmetic tests do not establish end-to-end coverage. RNG scope is explicitly modern CUDA Philox; old Thrust RNG is a distinct conditional source stream. CUB/CCCL association, shader contraction and CUDA cross-tree SHAP atomics remain numerical-validation limits, with exact integer contracts kept separate.
