# CUDA operation evidence map

This is a map of **42 operation families covering 109 CUDA source/header roots**
from the vendored XGBoost 3.4.2 import: 105 under `src`, plus four in the federated
plugin. It links CUDA sources to Metal dispatch points and existing tests.
**It is not a certificate of full parity.** A file can contain many operations;
file coverage and passing tests do not prove every branch or consumer is ported.
The machine-readable [map](../validation/cuda-operation-map.json) records the
baseline commit, inspected implementation revision, paths, status and limitations.

`python3 scripts/check_cuda_coverage.py` verifies that the original and current
CUDA inventories are both represented and that all referenced files exist.
It deliberately does not turn these structural checks into a correctness claim.
The implementation bodies behind the listed Metal interfaces live primarily in
`metal_histogram.mm` and `metal_histogram.metal`.

## Current work and validation boundaries

The [completion plan](PLAN.md) is the authoritative queue. The frozen
[caller/numerical audit](CUDA_AUDIT.md) at `382f78c` classifies 174 logical
operations and 1,078 lexical sites. Sixteen missing/defective rows map to ten
implementation tasks, including two correctness fixes. NUM-1 has since been
locally fixed at `2404827` ([evidence](../validation/cuda-num1-m3.txt)), and
PORT-9 at `1034657` ([evidence](../validation/cuda-port9-m3.txt)), and PORT-1 at
`c78cb43` ([evidence](../validation/cuda-port1-m3.txt)). PORT-2 is locally fixed at
`6a606e1` ([evidence](../validation/cuda-port2-m3.txt)), and PORT-3 at `ab87872`
([evidence](../validation/cuda-port3-m3.txt)). PORT-6 is locally fixed at
`2bfb914` ([evidence](../validation/cuda-port6-m3.txt)); four implementation tasks remain.
The frozen audit retains its original findings. PORT-4/5 classification
is complete for that ledger; full parity remains unproven.

The [review](REVIEW.md) records reproduced defects and architecture risks.
Existing [transform/linalg caller evidence](../validation/cuda-metal-transform-callers.txt)
should be retained. A missing generic helper launcher alone does not prove a
missing operation; actual production consumers determine coverage.

NVIDIA execution and other Apple hardware are not represented by M3 tests.
CUDA compilation/linking also passed at audit baseline `382f78c`
([run 41987882440](https://github.com/mmaaz-git/xgb-mps/actions/runs/41987882440)), including
NCCL, nvCOMP and federated consumers. See [compiler evidence](../validation/cuda-compile-ci-13.4.txt).
Compilation is not runtime or numerical equivalence. Performance follows
operation/storage correctness; historical timings are not current measurements.

mechanisms. “Audited with open tasks” links confirmed gaps in the JSON;
“classified consumers” closes only the frozen inventory classification. The JSON
contains full source lists, audited operation IDs and task references for each row.

## Scope decisions grounded in upstream

Column-wise data splitting was already removed in upstream import `22a84e0`:
`ValidateCAPIDataSplitMode` rejects it. It is not a missing Metal feature.
Refresh/prune, linear selectors/prediction, host model construction/serialization,
and approximate SHAP retain CPU work upstream; they do not all need new kernels.
CUDA/NCCL/nvCOMP runtime APIs are replaced by equivalent Metal operations and
transport/codec implementations, not by reproducing NVIDIA binary interfaces.
CuPy array methods outside XGBoost's result/input contract are not automatically
requirements for `MetalOutput`.

Native custom-gradient storage and ordinary native matrix entry storage have
been addressed since the initial audit. The latter includes sketch/compression
consumers, not only the importer. See
[native matrix storage validation](../validation/cuda-metal-native-csr-storage-m3.txt)
and [native gradient storage validation](../validation/cuda-metal-native-gradient-storage-m3.txt).
Detailed algorithm, arithmetic and historical validation records remain in
[CUDA_PARITY.md](CUDA_PARITY.md). Older broad statements there or in the development
log are historical evidence; the concrete open items above take precedence for
planning the next porting work.
