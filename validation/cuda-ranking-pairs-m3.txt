Implementation
--------------
Stable prediction ranks, stable descending labels, pair index i*k+repeat,
wrapped uint32(seed+query), independent Philox4x64 engine discarded by local
pair index, uniform_int_distribution<size_t> rejection over low bits. The
sample maps around its equal-label bucket. Homogeneous groups emit (0,0),
singleton ranges consume no draw. One GPU lane per pair. Raw pairs retain CUDA
orientation; gradient consumers canonicalize prediction-rank order before
applying the existing shared LambdaGrad formula.

A separate GPU query kernel links pair incidences in index order. This step
remains serial per query and is not a CUDA atomic gradient implementation.
Existing 64 MiB batch budgeting/reuse remains. Optional internal pair tracing
copies the actual sampled buffer before each reuse; production never allocates
that full trace. No CPU pair generation or adjacency construction in training.

Remaining ranking gaps
----------------------
CUDA uses a first gradient pass to calculate per-query deterministic rounding
factors, then truncates positive and negative gradient/Hessian contributions
before accumulation. That pass is not yet ported; do not infer gradient parity
from exact pairs. CUDA MAP statistics scan actual labels, while the current
Metal gradient cache counts labels exactly equal to one. CUDA combines query
weight with weight_norm before its final multiply; current Metal retains two
multiplications. CUDA unbiased cost rounding is also outstanding. The source
writes a single cost-rounding slot from all query lanes; its concurrency must
be resolved explicitly rather than silently copied. Actual libdevice rounding,
CUB scan association, cross-Apple validation and resident async state remain open.
