  arithmetic, diagnostic schema or tolerance changed.
  Authority: common/hist_util.cuh:250-307 keeps selected CUDA row/group weights on
  device. Group boundaries remain source-defined CPU metadata, uploaded as needed.
  CUDA itself finalizes cuts on CPU; that behavior is unchanged.

  Actual QuantileDMatrix plus host/disk ExtMemQuantileDMatrix constructors;
  unweighted, row, group and zero weights; empty, single and repeated variable
  batches; numeric/categorical/missing values; reference-cut reuse for every case.
  Shared/private MTLBuffer producers use strided weight views, reuse allocations,
  and poison data/weight buffers immediately after native import. Producers are
  released before completed matrices are consumed. Cache cleanup is checked.
  Native callbacks and final matrices inspect HDV device-only authority before
  CPU oracles. Zero vector readback, input staging, metadata host copy and adapter
  diagnostic readback are required during native construction. Group expansion
  must publish exactly rows*sizeof(float) GPU output; any staging is bounded by
  CPU group-pointer bytes. Reference cuts perform no sketch/weight expansion.
  Native cut checks use independent scalar CUDA-source sketch sort/prune/merge
  equations with exactly summable weights. Final CPU cut extraction is shared
  in this native fixture; the Python CUDA-source oracle independently checks
  end-to-end cut extraction, with exact bits and no tolerance adjustment.

  types, four weight kinds and native/mixed CPU+GPU data batches. Native metadata
  remains GPU-owned in mixed data batches. Both training and reference matrices
  are checked before getters; producer deletion, expected metadata, cut oracle,
  prediction consistency and cache cleanup follow. Zero-total-weight training
  uses an explicit base_score because its automatic weighted mean is undefined.
