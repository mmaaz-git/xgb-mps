Implemented
-----------
Query offsets start on the host, as in CUDA. Metal uploads an owned immutable
copy, computes adjacent differences, validates monotonicity, and reduces the
maximum query size on GPU. Mean pair counts are n*k; top-k uses the same integer
trapezoid area as CUDA. Counts are written as [0, count0, count1, ...] and scanned
with the existing recursive 256-entry uint64 GPU prefix implementation. Metal's
256-pair tile counts and prefixes use the same integer machinery. Pair totals
never pass through floating-point arithmetic. No row/pair allocation is needed
to build this metadata, including logical totals close to UINT64_MAX.

The GPU-built task buffer itself feeds pair sampling, gradients, normalization
and gathers; there is no host reconstruction/upload of its counts or prefixes.
RankingCache owns a shared immutable RankingPlan. Objective calls, cached sorts,
NDCG initialization and precision/NDCG/MAP scoring retain/reuse its GPU offsets
and tasks. Existing parameter/MetaInfo cache renewal creates a new plan.
Standalone sort and grouped ROC/PR-AUC calls also obtain maxima on GPU.
The old MPS host maximum loop in RankingCache and the host task-prefix loop in
RankingGradient are gone. The CPU path's maximum computation is unchanged.

The host reads the completed scalar maximum and shared task metadata to allocate
buffers and schedule 64 MiB pair batches. It checks cached group identity with
memcmp and rejects mismatched pair parameters. Input ownership is independent
of callers' vectors. These host validation/scheduling operations and the initial
GPU wait are explicit; this is not complete asynchronous ranking execution.
Gradients, row data, discounts and bias state still stage through host memory.

Counters: ranking_plan_dispatches counts successful metadata builds,
ranking_plan_reuses counts validated supplied-plan uses, and
ranking_plan_gpu_time_ns measures these commands. GPU timings exclude host
allocation, waits, validation and scheduling. They are separate from subsequent
sort/objective GPU command durations. Statistics and internal ranking signatures
changed, so the full validation rebuilds all native binaries.

  Independent unsigned __int128 source-formula oracle plus nested-loop pair

  Malformed/descending offsets are rejected. Every valid case checks the
  production GPU metadata counter.

Cache tests instantiate the actual RankingCache on MPS, check its maximum and
bias-position size, reuse its storage for three exact stable sorts, then retain
its plan beyond the cache lifetime. Both methods produce bit-identical cached
and fresh gradients for seeds 0, 919 and UINT32_MAX. Caller offset mutation does
not modify the plan; stale groups, changed k and changed pair methods are rejected.

Public Python tests add six objective/cache lifecycle cases: three objectives
and both pair methods. Three boosting rounds reuse one plan; changing k or the
MetaInfo object renews it, including a different query layout with the same row
count. Saved-model CPU predictions retain the existing 2e-5 tolerance. Existing
NDCG metric tests now assert one metadata build and four uses over three evals.

Limits
------
This establishes exact metadata/formula checks on Apple M3, not NVIDIA-device
execution equivalence or cross-Apple validation. It does not change the ranking
arithmetic edge policies documented in cuda-ranking-arithmetic-m3.txt. Existing
gradient, pair-order, bias-update and precision tolerances are retained.
Remaining full-port work includes host metric final reductions, AFT's CPU
corrections, adapter/device-array
sketch ingestion, generic metadata/category operations, objective/state work,
Apple array interoperability, distributed collectives and persistent asynchronous
ownership. No full CUDA-operation parity or performance improvement is claimed.
