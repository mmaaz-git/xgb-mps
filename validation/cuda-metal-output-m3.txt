Scope and source authority
--------------------------
Vendored c_api/c_api.cu::InplacePreidctCUDA sets the prediction's device and
returns ConstDevicePointer. Python _prediction_output/from_array_interface then
make an independently owned CuPy copy by default. Upstream batch prediction
returns a host pointer. This fork adds explicit output_device="mps" to both
batch and inplace prediction while preserving default NumPy/CuPy results.
Selecting output storage does not change the execution device or algorithms.

MetalOutput owns a private float32 Metal allocation independently of the model,
mutable prediction cache and subsequent predictions. Shape metadata is read in
Python; output payload never converts through a NumPy array on this branch.
Eligible host prediction spans are GPU-blitted to the private snapshot; other
spans use a counted host upload fallback. Explicit numpy() performs readback.
Actual PyTorch and MLX DLPack consumers use the output on GPU, and outputs can
feed native features, metadata and custom-gradient inputs again.

Each legacy/versioned managed export retains allocation ownership independently.
Default/False copy shares writable storage. True makes a separate GPU copy and
sets the versioned IS_COPIED flag. Native capsule names/destructors handle both
unconsumed capsules and consumer-renamed capsules without Python callbacks.
The optional CPython bridge resolves the running interpreter's C API via dlsym;
native clients can invoke managed-tensor deleters without Python linkage.

Tree/SHAP outputs and prediction transforms now use guarded shared host-memory
bindings where eligible. Argmax compaction and aliased SHAP margins retain
separate GPU input snapshots to prevent read/write races. Existing kernels and
numerical tolerances are unchanged. Read-only source imports and unaligned
readback destinations exercise the safe fallback. Generic HostDeviceVector,
cache copies, margin initialization and host feature/model preparation remain
host-owned. This is not an end-to-end device ownership or zero-copy claim.
Linear prediction still uses CPU computation as upstream does; its output can
be stored on GPU. No CUDA-to-Metal transfer is provided.

Snapshot commands complete synchronously. Loaded PyTorch/MLX queues synchronize
before re-export/readback. Generic consumers must complete writes themselves;
only stream=None and Metal device 0 are accepted. Portable asynchronous Metal
queue handshakes and general stream parity remain open.
