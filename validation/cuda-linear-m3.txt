CUDA-source linear coordinate descent on Apple M3
Date: 2026-11-04
Source base: ce05578 plus the linear-alignment change accompanying this record.

Authority and changes:
  linear/updater_gpu_coordinate.cu GetBiasGradient/GetGradient reduce FP32
  GradientPair via common/device_helpers.cuh SumReduction (CUB DeviceReduce::Sum).
  All Hessians participate in device sums/residuals. Feature terms are g*x and
  (h*x)*x. Feature residuals use (h*delta)*x, then GradientPair += (term,+0).
  Bias skips delta=0; feature updates do not. Host selectors receive the original
  input gradient snapshot even after bias/residual updates; no final copy-back.
  Metal now follows these rules, replacing the earlier CPU-based f64/filter/
  residual order and refreshed selector snapshot. Host selection/scalar model
  updates remain host, as CUDA specifies. Input gradients remain unchanged.

Reduction and domain limits:
  Recursive 256-thread FP32 trees, with eight 32-lane groups and raw-bit shuffles.
  All levels return GradientPair (FP32), including overflow. Arithmetic helpers
  preserve subnormals under Metal FTZ. No binary64 sum accumulator remains here.
  This is not an emulation of a specific CUB architecture/tile policy. NVIDIA
  documents that legacy DeviceReduce floating-point sums can differ across GPU
  architectures. Exact NVIDIA execution and NVCC contraction remain unverified.
  https://nvidia.github.io/cccl/unstable/cub/api/structcub_1_1DeviceReduce.html
  Reduction lengths above INT32_MAX are rejected to avoid CUDA-interface narrowing.
  Sorted duplicate CSC rows are processed serially on Metal. CUDA's concurrent
  per-entry writes race for duplicates; no NVIDIA-equivalence claim is made for
  this extension. Distinct-row CSC semantics follow source. Multi-page input is
  rejected upstream and here. Cross-round buffer reuse remains unimplemented.

Native validation: tests/metal_linear_api.cc
  PASS 49 cases / 4,118,809 source pairs / 3,564 sum fields (2,991 exact or nonfinite
  classification) / 148,277,125 residual fields. Metal API Validation enabled.
  Finite residuals retain exact bit comparisons; NaNs use classification.
  FP32 sums use an independent high-precision reference of source terms. When
  sum(abs(terms)) fits the common dyadic lattice in 24 significand bits, exact
  comparison is required. Otherwise use gamma_d * sum(abs(terms)), d=8 per recursive
  256-element level, u=2^-24, gamma_d=d*u/(1-d*u). Maximum error/bound=0.0987717202.
  This is the explicit new FP32 contract, not a widened failed binary64 tolerance.
  Empty/million-row inputs, multiple groups, subnormals/large/nonfinite values,
  negative Hessians, duplicate runs, guards, input preservation and errors retained.
  New exact differences: negative-H sums/residuals, zero bias bypass vs zero feature
  execution (+0 Hessian and 0*infinity -> NaN), FP32 overflow, multiplication-order
  fixture h=0x401758e3, step=0x3fd4c3f0, x=0x3f807d7e gives CUDA0x407c898a vs CPU...8b.
