Direct GPU adapter-to-ELLPACK construction
========================================
Machine: Apple M3 Air, 8 CPU / 10 GPU cores, 16 GB unified memory.
Date: 2026-11-04. Coverage/ownership work; no new performance benchmark.

Scope and CUDA authority
-----------------------
ExtMemQuantileDMatrix(iterator, device="mps") with on_host=True now writes
compressed cache pages directly from resident adapter values and row pointers.
No temporary host GHistIndexMatrix or column mirror is allocated during input
construction; no quantized-bin GPU->host->GPU roundtrip is used. Disk construction
keeps its existing gradient-index format and shared MakeIndexBatch helper.

Vendored source authority: data/ellpack_page.cu::WriteCompressedEllpackFunctor,
CopyDataToEllpack, TupleScanOp, WriteNullValues and the adapter constructor.
Dense/relatively dense pages write feature-local bins at their feature positions;
relative layouts include explicit missing symbols. Sparse layouts preserve
compacted feature order, write global bins, then fill trailing null symbols.
The existing numerical upper-bound/categorical integer-conversion/lower-bound
search was extracted unchanged into one Metal helper used by both binning paths.

The adapter's raw 2^26-slot windows remain unchanged. A compressed page's ordered
BeginAdapter/PushAdapter/EndAdapter lifecycle checks contiguous windows and full
input coverage. Sparse row positions persist in GPU-private storage across partial
rows; no row-position readback is needed. Cut/type descriptors upload once per
input page. Dense and zero-stride pages do not allocate full-row cursor storage.
Existing raw preparation checks/metadata reads remain; a four-byte status checks
compressed-write errors. Infinity, missing cut segments, invalid row width, feature
count mismatch and incomplete/out-of-order construction are rejected. The public
iterator checks still enforce rows, nnz and number of batches across both passes.

Three appended Statistics fields:
- ellpack_adapter_dispatches: completed direct writes and sparse null completion.
- ellpack_adapter_values: non-missing values successfully binned by direct writes.
- ellpack_pack_input_bytes: host bins/row-pointer bytes uploaded by the older
  Pack(GHistIndexMatrix) conversion (cut descriptors excluded).
Direct cache construction requires unchanged host-pack bytes, adapter_index_dispatches,
binning_dispatches and raw/compressed diagnostic readback. These distinguish direct
GPU construction from an equivalent result obtained through host-bin staging.
GPU time uses ellpack_gpu_time_ns; CPU-only counters are zero. Native callers must
rebuild for the extended Statistics ABI; the full regression rebuilds all of them.

Focused native validation
-------------------------
New tests/metal_ellpack_adapter_api.cc, registered with MTL_DEBUG_LAYER=1.
PASS 73 cases / 2,933 windows / 81,666 exact compressed bytes / 7,455,890 checked
fields / 12 expected errors. Log: results/test-direct-ellpack-native-v2.log.
The fixture's first compile had a helper named Array, ambiguous with xgboost::Array;
renaming the fixture helper fixed compilation. No production correction or relaxed
tolerance was required by this test run.

Independent CPU lower/upper-bound searches on raw values supply expected bins.
The upstream scalar CompressedBufferWriter supplies expected bytes. Restoration
is checked against exact row pointers, global bins and hit counts; GPU buffers
must remain attached. Production raw/quantized staging counters must not increase.
Cases cover:
- 3/17/257/65537 max bins, including 8/16/32-bit restored dense indices.
- Dense, relatively dense, sparse and all-missing layouts; empty input and cuts.
- Float and double input; categorical fractional codes, subnormals, signed zero,
  values beyond the last cut and missing sentinels.
- 1/5/19/4096-slot windows, repeatedly split sparse rows and 4097-row prefix cases.
- Shared/private cache splits and restoration with/without prefetch copying.
Twelve expected failures cover incomplete input/commit/copy, duplicate Begin,
missing Begin, out-of-order/repeated windows, wrong features, infinity, missing
values in a declared-dense page, missing cut segments and too-small row stride.

Public and integrated validation
--------------------------------
Existing host-cache tests now require direct dispatches, the exact non-missing
value count and absence of host-bin staging. Existing external native cases also
check direct counts/no staging for all 144 host-cache configurations. The complete
external suite passes 192 cases / 2,322 cached-page visits / 10,816,123 exact fields.

New tests/test_metal_direct_ellpack.py: 13 cases.
- Ten numeric input types with reversed strides; fixed-cut prediction agreement,
  same-model CPU prediction and no staging/files.
- The real 2^26-slot boundary splits a sparse seven-feature row after feature 3;
  valid features 0,2,4 require a persistent row cursor across that seam. The fixture
  broadcasts a seven-value row over 9,586,983 rows (28,760,949 non-missing values).
  Reference cuts bypass large sketch sorting. Two direct write dispatches plus
  one null-completion dispatch are required; constructor checks restored nnz.
- A changing iterator preserves total nnz but increases the maximum row width;
  construction must reject it before writing outside the compressed row.
- Infinity rejection and an infinity missing sentinel.
All 13 passed in 1.18 seconds (results/test-direct-ellpack-public-extra-v1.log).
The existing host/disk/in-memory construction suite passed 197 cases in 13.32
seconds (results/test-direct-ellpack-public-v1.log). Combined focused coverage: 210.

Limits and remaining work
-------------------------
This removes input bin staging for external host caches. Restoration still creates
host gradient-index/column mirrors and GPU uncompressed indices; current consumers
do not read the compressed cache directly. Ordinary/in-memory matrices retain their
existing index representations. Host input packing/uploads, metadata/dictionaries,
synchronous orchestration, optional Snappy/nvcomp cache compression/decompression,
native Apple device-array/half input, generic device ownership and GPU collectives
remain unfinished. Apple private/shared storage both use unified memory.
No new speedup, NVIDIA execution equivalence or cross-Apple validation is claimed.
