Metal disk-backed ExtMemQuantileDMatrix construction
==================================================
Machine: Apple M3 Air, 8 CPU / 10 GPU cores, 16 GB unified memory.
Date: 2026-11-04. Coverage/correctness work; no new benchmark.

API and scope
-------------
ExtMemQuantileDMatrix(iterator, device="mps", max_bin=...) now accepts dense and
columnar host batches. DataIter must use on_host=False. The optional C API JSON
device field selects construction independently of booster device. Defaults
retain upstream input-device inference, including the existing CPU path.

The shared metal_impl::MakeSketches and AdapterWindows now serve both in-memory
and disk-backed quantile construction. Existing raw 2^26-slot adapter windows,
GPU decode/missing/category recoding, counts/prefix/compaction, resident CUDA-
derived summaries, group-weight expansion and GPU bin assignment are reused.
No duplicate sketch algorithm or CPU fallback for raw-value binning was added.

CUDA source authority in vendored xgboost/src:
- data/quantile_dmatrix.cu::cuda_impl::MakeSketches
- data/extmem_quantile_dmatrix.cu::ExtMemQuantileDMatrix::InitFromCUDA (disk branch)
- data/ellpack_page_source.cu::ExtEllpackPageSourceImpl::Fetch
- common/hist_util.cu/.cuh adapter frontend, common/quantile.cu summaries
- data/ellpack_page.cu row counts and page/bin construction

The second pass builds one GHistIndexMatrix per callback batch, bins on GPU,
constructs the host column mirror from quantized data, and writes the existing
gradient-index disk format. There is no full-dataset GHistIndex allocation.
Completed reads use existing prefetch/mmap, with no iterator calls or resketch.
Metadata remains host-aggregated, as does cache I/O. Constructor checks validate
rows, nnz and batch counts across passes. Partial files are removed on failure,
and the completed cache is removed when the DMatrix is destroyed.

A real multi-page crash exposed global-base indexing in two host conversion
helpers. ColumnMatrix::InitFromGHist dense offsets and AssignColumnBinIndex sparse
offsets now address page-local storage. Native tests independently verify every
column/bin for nonzero-base pages. Existing CUDA conversion is whole-matrix and
requires matching total rows, so it did not exercise these later-page offsets.

Limits and remaining work
-------------------------
This is the disk-backed construction path, not the entire CUDA external-memory
cache subsystem. on_host=True, adaptive host/device cache ratios, cache-page
concatenation, device-owned compressed storage, native Metal array/half input,
metadata/device ownership and distributed GPU collectives remain unfinished.
Current quantized matrix ownership and column storage remain on the host; page-
owned Metal copies used during training do not establish full device ownership.
Raw adapter packing/upload, dictionary ownership, synchronization and cache I/O
are still host work. Counters are reused; no Statistics ABI change this step.

No measured NVIDIA equivalence, cross-Apple validation or new speedup is claimed.
Native exact comparisons isolate CPU bin assignment at shared cuts; the separate
cut oracle follows CUDA algorithms and declares Metal FP32 scan association.
