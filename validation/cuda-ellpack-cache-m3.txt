Metal ELLPACK compression, concatenation and external host cache
==============================================================
Machine: Apple M3 Air, 8 CPU / 10 GPU cores, 16 GB unified memory.
Date: 2026-11-04. Coverage/correctness milestone; no new benchmark.

API and source authority
------------------------
ExtMemQuantileDMatrix(iterator, device="mps") now accepts DataIter(on_host=True),
the default. cache_host_ratio selects shared/private storage; min_cache_page_bytes
selects concatenation. No disk file is created. on_host=False remains disk-backed
and rejects an explicit cache_host_ratio. Default input-device inference is unchanged.

Vendored CUDA authorities:
- data/ellpack_page.cu::CalcNumSymbols, CopyGHistToEllpack, Copy
- common/compressed_iterator.h::CompressedBufferWriter, SymbolBits, kPadding
- data/ellpack_page_source.cu::CalcCacheMapping, EllpackHostCacheStreamImpl::Write/Read
- data/batch_utils.cc::DftPageSizeHostRatio
- data/extmem_quantile_dmatrix.cu::InitFromCUDA

Metal kernels implement the eight-byte prefix and MSB-first bitstream, dense local
bins, relatively dense local bins plus null, sparse global bins plus null, bitwise
page copies across non-byte-aligned seams, row counts/prefixes, restoration and
hit counts. GPU buffers preserve the compressed stream across shared/private byte
splits, including a split inside a symbol. CUDA's minimum empty stream is nine
logical bytes; physical Metal allocations have at least 16 bytes.

Plan defaults preserve CUDA's page grouping and padded input-byte sums. The default
minimum page size is device budget / 16; cache budget is device budget / 2. Auto
validation ratio is one; train ratio is zero if the cache fits, otherwise
(total - cache_budget * 0.85) / total. Explicit ratios are checked in [0,1]. A cache
containing just one page forces ratio zero even for explicit ratios, as CUDA does.
Metal substitutes recommendedMaxWorkingSetSize for physical CUDA device memory.
Apple has no corresponding NVIDIA C2C link-count branch.

Shared/private buffers both use unified memory; private storage restricts CPU
access. This policy does not establish additional VRAM capacity or memory savings.
Primary Apple references:
https://developer.apple.com/documentation/metal/mtldevice/recommendedmaxworkingsetsize
https://developer.apple.com/documentation/metal/choosing-a-resource-storage-mode-for-apple-gpus

Ownership and cache lifecycle
-----------------------------
MetalPageSource uses existing SparsePageSourceImpl asynchronous prefetch/reset
machinery with a two-page prefetch window (active plus prefetched). Cache construction
keeps one input page and one aggregate compressed page, without a full-dataset
gradient-index allocation. Completed construction retains no input callback or raw
array references. GPU prefetch can join split pages; wholly private pages alias
their existing storage. Restored index/row-pointer buffers attach directly to
training pages, avoiding a repeat upload of the host bin mirror.

MakeIndexBatch is shared with disk construction. Quantized bins still return from
GPU adapter binning to a temporary host GHistIndexMatrix before upload for packing.
Restoration also builds host gradient-index and column mirrors for existing CPU
interoperability. These are explicit remaining ownership/staging gaps; the new
compressed cache does not imply an entirely device-owned training pipeline.

Eight Statistics fields appended; all native callers rebuilt:
ellpack_pack_dispatches (includes symbol maxima), ellpack_copy_dispatches,
ellpack_restore_dispatches, ellpack_cache_dispatches (buffer blits),
ellpack_gpu_time_ns, ellpack_debug_readback_bytes, ellpack_cached_host_bytes,
ellpack_cached_device_bytes. Cache-byte totals are cumulative logical committed
bytes, not live allocation gauges; dummy minimum allocations are excluded.
GPU timing excludes host staging/metadata/column mirrors; dense transpose retains
its existing index counter. Production compressed-byte diagnostic readback is zero.
CPU-only builds expose zeros and reject MPS construction clearly in both cache modes.

Remaining scope
---------------
Direct adapter-to-compressed construction, direct compressed training/prediction
consumers, optional Snappy/nvcomp cache compression/decompression, native Metal
array/half input, general metadata/device ownership and GPU collectives remain
unfinished. Host packing, dictionaries, allocation and synchronization remain.
This step covers external host-cache ELLPACK; ordinary/in-memory matrices still
use their existing index representations. No benchmarks were rerun. No measured
NVIDIA equivalence or cross-Apple validation is claimed.
