Compressed ELLPACK consumers on Metal
====================================
Machine: Apple M3 Air, 8 CPU / 10 GPU cores, 16 GB unified memory.
Date: 2026-11-04. Coverage/ownership work; no new benchmark.

Implementation and authority
----------------------------
External host-cache training pages retain compressed GPU head/tail buffers and
their geometry/cuts. No restored GPU index array, row-pointer array or dense GPU
transpose is retained. Split views and joined prefetch copies both work, including
symbols crossing the shared/private boundary. Buffers remain owned after the source
compressed-page object is destroyed.

CUDA source authority:
- data/ellpack_page.cuh::EllpackAccessorImpl::GetBinIndex/NullValue
- tree/gpu_hist histogram and partition consumers of the ELLPACK accessor
- predictor/gpu_data_accessor.cuh::EllpackLoader::GetElement

The compressed accessor reads local feature bins for dense/relatively dense data,
and binary-searches global bins within a padded sparse row. It recognizes null
symbols and applies feature offsets. Prediction reconstructs category values,
negative infinity for the first numeric bin, or the previous cut. GPU category
mapping retains existing behavior.

Global/shared histogram and partition kernels share their arithmetic bodies with
the legacy typed-index kernels through bool template specialization. Legacy entry
point layouts remain unchanged. Histogram modular integer sums, the small-bin SIMD
path, shared accumulation, node/row addressing and gradient state are unchanged.
Partition classification uses compressed lookup before the existing stable
prefix/scatter stages. Prediction/SHAP input preparation reads compressed buffers
directly instead of packing/uploading the host bin mirror. Raw and ordinary typed
input paths retain their existing behavior.

Three Statistics fields appended, with CPU-only zeros:
ellpack_histogram_dispatches, ellpack_partition_dispatches, ellpack_input_dispatches.
These count completed direct consumer commands, excluding empty inputs. Existing
histogram/shared/partition/input/map counters remain in use. Native callers must
rebuild; full validation does so. No bin re-upload, repeat restoration or diagnostic
compressed readback is permitted during the native consumer checks.

Native validation
-----------------
New tests/metal_compressed_consumers_api.cc, MTL_DEBUG_LAYER=1.
PASS 139 cases / 28,485,537 exact fields / 278 histogram builds / 1,946 partitions /
417 prediction input chunks. Focused log results/test-compressed-consumers-native-v2.log.
Initial fixture compilation needed an explicit unsigned-to-bst_bin_t cast and the
actual Statistics field name shared_histogram_dispatches. Production numerical
code/tolerances did not change to satisfy this fixture.

Independent CPU GHistIndex construction supplies bins. Scalar gradient sums and
stable row classification supply expected histograms/partitions. Scalar CUDA-style
cut reconstruction and category mapping supply expected prediction input values.
After cache restoration the fixture destroys the original compressed page and
overwrites the host bins, row pointers and cut values. GPU results must still match.
Restoration must not create a dense GPU transpose; consumer calls must not upload
host bins, repeat restoration or read compressed bytes back to host.

Cases include 2/17/257/65537 max bins; dense, relatively dense, sparse, all-missing
and empty layouts; empty feature segments; ratios 0, 0.000001, 0.5 and 1; prefetch
copy true/false; nonzero page bases and independently retained split buffers.
Histograms use reversed/subselected global rows and signed exact gradients.
Partitions cover every feature, categorical words and both missing directions.
Prediction chunks cover first/interior/empty ranges, extra output columns and
category mapping. NaNs compare by classification, all other prediction values by
bits. Six 16,513-row dense cases exercise shared register/SIMD and shared-array
histograms; a 5,000-row sparse case exercises the non-serial partition prefix.

Remaining scope
---------------
Host gradient-index/column mirrors are still built eagerly for CPU interoperability
and existing DMatrix contracts. Their temporary GPU unpacking/readback remains;
only the retained consumer view is now compressed. Ordinary/in-memory matrices
still use typed GPU indices. Lazy host mirrors, their ownership/call-site audit,
optional Snappy/nvcomp cache compression, native Apple array/half input, general
metadata/state ownership and GPU collectives remain unfinished.
No new performance, whole-process memory, NVIDIA-equivalence or cross-Apple claim.
