Vector model-buffer copies and learning-rate scaling on Apple M3
Date: 2026-11-04
Source base: 08d3909 plus the model-state change accompanying this record.

Authority and scope:
  xgboost/src/tree/multi_target_tree_model.cu CopyBatch uses device-to-device
  batched memcpy for float weights and uint32 category words. ApplyLearningRate
  uses thrust::transform with one ordinary FP32 weight * eta operation.
  The MPS branches now use Metal blit copies and a compute scaling kernel.
  CPU and CUDA branches are unchanged. No NVIDIA hardware execution was run.
  Host model allocation, resize and metadata remain; this is not persistent
  end-to-end GPU ownership. Scalar tree eta application stays host like CUDA.

Implementation checks:
  Bit-preserving copies; destination ranges checked for bounds and overlap.
  Original inputs snapshotted on aliases; frontend snapshots old model aliases
  before HostDeviceVector growth. Holes, old nodes and output guards preserved.
  Guarded synchronous borrowed host memory, with initialized staging fallback.
  Scaling uses the exact binary64 product of two FP32 values then one FP32
  rounding, implemented on Metal with integer-backed arithmetic. Raw-bit loads
  and stores retain subnormal values. NaN arithmetic payload is not specified.
  Empty operations return without GPU work. Counters report completed copies,
  scaling, copied words and command time; CPU-only API exposes zero values.
  Statistics ABI changed; all native API tests were rebuilt in the full run.

  unaligned buffers, read-only sources, arbitrary bits including sNaN/qNaN,
  signed zero, subnormals and infinities; prefix/hole/suffix guards checked.
