Federated Metal collectives and learners — Apple M3, 2026-11-04 local
==================================================================
Scope: all four CUDA federated collective adapters, the variable GPU reduction
fallback and production sketch/learner consumers, including mutual TLS.
Optional feature flag: PLUGIN_FEDERATED=ON, with USE_METAL=ON for Apple GPU work.

Source authority:
- plugin/federated/federated_coll.cu: CUDA stages GPU data to host vectors, calls
  the existing FederatedColl RPC methods, then copies received data to CUDA.
  Fixed reductions execute on the server, not in local CUDA kernels.
- collective/in_memory_handler.cc::AllreduceFunctor: actual server dtype/operator
  contract, distinct from NCCL's FP16 and floating-bytewise support.
- collective/allreduce.h::gpu_detail::AllreduceVHostFallback: gather payloads,
  rank zero folds peers in ascending order on GPU, then broadcasts the result.
  This is different from NCCL's binomial grouping for non-associative sketches.
- common/quantile.cu::SketchContainer::AllReduce returns immediately for world=1,
  including a tracker-connected single worker.
- c_api/coll_c_api.cc::XGTrackerFree calls Tracker::Stop before waiting. The
  federated tracker had Shutdown but inherited the base no-op Stop.

Implementation:
- MetalFederatedColl holds the same FederatedColl owner as CPU control messages,
  preserving one request sequence. RPC serialization/receipt accesses shared
  Metal allocations directly; there is no HostDeviceVector host mirror. Callers
  retain owners, producers complete before entry, and RPC completion precedes
  subsequent GPU consumers. This is a synchronous path.
- Allreduce, broadcast, allgather and variable allgather validate local shape,
  root, dtype and operation contracts. Supported arithmetic types are FP32/FP64
  and signed/unsigned 8/32/64-bit integers. Bitwise operations require integers.
  The server does not implement FP16, 16-bit integers or floating-point bitwise
  reductions; the Metal adapter rejects them before consuming a sequence number.
- Federated AllreduceV gathers owned Metal buffers, GPU-copies each peer segment,
  folds peers 1..world-1 at rank zero, then broadcasts size/payload. All sketch
  merge/prune arithmetic stays on GPU. The TCP/NCCL-style branch is unchanged.
- Metal sketch reduction now skips an attached world=1, matching CUDA.
- The former MPS federated guard is removed after both fixed and variable paths
  were implemented. Existing row-partitioned hist/approx/DART learners use them.
- Apple builds omit GNU --exclude-libs,ALL. A scoped gRPC header preserves
  XGBoost logging/check macros around modern Abseil-generated includes.
- FederatedTracker::Stop now invokes Shutdown, so public tracker cleanup stops
  the server instead of waiting on a running gRPC service indefinitely.
- scripts/test_federated.sh builds separately in build-metal-federated and uses
  results/federated-python, leaving the ordinary library/package path intact.
  It also runs two-worker mutual TLS with temporary, locally generated test
  certificates. Keys/certificates are removed after the run.

Development findings and fixes:
- First federated compilation failed because new gRPC/Protobuf includes replaced
  XGBoost LOG with Abseil LOG, which does not accept CONSOLE. Header macro scoping
  fixed the build; both CPU-only and Metal optional builds now compile.
- First native fixture compilation had a Value helper ambiguous with XGBoost's
  JSON Value class. Renamed the test helper; no production arithmetic change.
- Transport world=1 passed, but server cleanup hit the test's ten-second stop
  deadline. Source inspection identified the missing Stop override; fixed it.
  A separate test-server process gives bounded cleanup on worker failures.
- The first two-worker learner run trained and validated its Metal model, then
  failed in the CPU reference: HostSketchContainer requests peer channels that
  FederatedComm explicitly forbids. This upstream CPU path is unchanged. For
  unsampled exhaustive numeric bins, reference training now uses pooled inputs
  after communicator finalization. The original 2e-5 absolute/relative tolerance
  is unchanged. The GPU sketch has a separate CUDA-derived federated-fold oracle.
- Expected feature_types differences on empty workers remain separately asserted
  as in the preceding learner checkpoint; every other serialized model field is
  compared. Quantile learner fixtures retain their explicit intercept, with
  automatic initialization behavior covered by the existing native tests.

Limits:
- Tests share one physical Apple M3. No cross-machine or NVIDIA execution.
- This ports the CUDA-defined federated paths; it does not add distributed
  gblinear, which remains unsupported upstream.
- GPU operations complete synchronously. Portable stream handshakes and other
  operation/state audits remain unfinished; full CUDA parity is still active.
- Shared logging/header and tracker changes affect CUDA builds too. Their CPU
  and Metal builds are validated; NVIDIA compilation/execution is not available.
- Federated CPU sketching's peer-channel failure remains upstream behavior. A
  disconnected/missing worker can still leave the upstream server handler waiting;
  test-process isolation is cleanup, not a new production fault-tolerance claim.
- gRPC/Protobuf versions tested: 1.85.1 / 36.2 (Homebrew arm64 bottles).
- No benchmark or new performance claim accompanies this checkpoint.
