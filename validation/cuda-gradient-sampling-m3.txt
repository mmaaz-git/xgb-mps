Date: 2026-11-03 America/Los_Angeles (2026-11-04 UTC)
Machine: MacBook Air, Apple M3 (8 CPU / 10 GPU cores), 16 GB, macOS 26.6.2.

Scope
-----
Production MPS sampling now uses the original per-target integer gradients and
scales. It computes binary64 norm terms, FP32 target reductions/square roots,
sorted norms, CUDA-quantized integer prefixes, first-valid thresholds, Philox
selection, binary64 rescaling and integer requantization on Metal. Saved norms,
threshold and seed replay sampling onto arbitrary FP32 value-gradient layouts.
Histograms and all roots retain the sampled integer state. CPU sampler unchanged.

CUDA source authority: tree/gpu_hist/{sampler.cu,sampler.cuh,quantiser.cuh},
tree/hist/sampler.h and common/random.cuh. The modern CCCL RNG and fixed-segment
SM60-SM90 reduction policy are pinned to NVIDIA/cccl commit
3d0d040ac0dc5907daf2a0731edb378e5562099d.

No NVIDIA hardware execution comparison was performed. The explicit norm FMA
model and Metal bound-reduction order require validation against actual NVCC/GPU
configurations; older Thrust and newer architecture policies may round differently.
Nonfinite norms with nonzero budget and rescaled coordinates outside int64 range
raise errors; CUDA C++ conversions are undefined there. These tests do not claim
portable CUDA output equivalence for that domain. No performance benchmarks run.

Public training validation
--------------------------
CPU custom objectives now receive independent CUDA-derived gradient sampling
instead of invoking CPU's distinct sampling algorithm. Original rtol/atol=2e-5
checks remain, including scalar/vector training, reduced leaf fitting, external
pages, regularization, clipping and resumed models. The public objective interface
is FP32, so these are downstream prediction comparisons; native integer checks
provide the stronger exact-state evidence.
Eight new hist/approx forest cases check exact root predictions, original-state
reuse and per-tree/round/target seed consumption against integer-derived roots.
The previous eight uniform-forest cases remain.
Legacy CPU-formula low-level sampler tests still pass; production no longer calls
that API. Its old CPU-vs-MPS production assertion was replaced with the independent
CUDA-formula lifecycle tests above, not relaxed.

Initial diagnostics and corrections
-----------------------------------
Initial API test compilation exposed only fixture shape/Span API mistakes.
The first executed API run hit a real rescaling-domain boundary in a wide-target
fixture. The production check already rejected it. The host oracle was corrected
to check the domain before conversion (avoiding undefined host casts), and the
suite now explicitly requires matching rejection for seven such cases.
No production numerical fix or tolerance relaxation was needed after these runs.
