Host mirrors on demand for Metal compressed caches
==================================================
Machine: Apple M3 Air, 8 CPU / 10 GPU cores, 16 GB unified memory.
Date: 2026-11-04. Coverage/ownership work; no new benchmark.

Implementation and source contract
----------------------------------
CompressedPage::View acquires a retained GPU head/tail/cut view, preserving split
storage and optional private prefetch copies. It sets explicit device row metadata
without allocating host rows/bins/hits/columns. GHistIndexMatrix::Size no longer
requires a row-pointer array for these views. Host-only helpers and invalidation
reject a device-only page instead of silently using absent data; raw public host
arrays are documented as unavailable on MPS batches until materialization.

MaterializeHost explicitly runs the existing GPU count/prefix/unpack pipeline,
copies rows/bins/hits and initializes CPU columns. It retains the same compressed
GPU view, is idempotent, and never re-uploads host bins. Legacy Restore calls View
then MaterializeHost, preserving its eager diagnostic/conversion behavior.

MetalPageSource workers always create device-only views. Only the iterator thread
materializes a current page on CPU request. Reset and device selection share the
existing single-threaded iterator lock. The generic reset body was extracted as
protected ResetCache without changing ring/fetch behavior. Workers never read the
mutable device flag, so retained prefetch futures are independent of CPU/MPS mode.

Constructor nnz validation still counts actual compressed symbols on GPU, reads
one scalar per completed cache page, and checks ext.nnz. It does not infer validity
from empty host arrays or discard the former nnz check. Prediction's shared view
now fetches columns inside CPU DoFill, not when constructing a Metal-capable view.
Cut export/reference lookup request only metadata and do not force a host mirror.

Authority: CUDA EllpackAccessor/consumers keep compressed device representation;
iterative_dmatrix.cc::GetGradientIndex explicitly creates CPU representation when
needed. This fork preserves its already-supported external MPS CPU interoperability.
Approximate SHAP remains CPU code; shap.cu rejects approximate contributions and
interactions. Its MPS fallback now passes a CPU context so host batches are explicit.
No new approximate GPU implementation or altered numerical tolerance is claimed.

Statistics ABI extended by four fields (all native callers rebuilt in full run):
ellpack_view_pages, ellpack_count_dispatches, ellpack_host_materializations,
ellpack_host_readback_bytes. View pages count acquisitions; count dispatches count
constructor/diagnostic scalar-count commands. Host materializations count completed
explicit conversions. Readback bytes are rows*8+8, typed bin bytes, and GPU hit
counts*4; construction's scalar is separate. Existing ellpack_restore_dispatches
counts only explicit host count/prefix and unpack commands. CPU-only values zero.

Failures investigated
---------------------
- First build: row-prefix helper accepted const Runtime but existing prefix encoder
  needs Runtime&. Fixed qualification; build v2 passed.
- New external-cache fixture omitted PrepareInput's explicit empty mapping argument.
  Fixed the call; the consumer suite had already passed, so only the failed native
  suite/public tests were repeated next.
- Initial 15 new public cases exposed approximate SHAP's implicit CPU path trying
  to read a device-only page. Fixed production fallback to request CPU batches;
  assertions now distinguish CUDA-supported GPU modes from this explicit CPU path.
  Focused public v3 passed 136 cases before the extra booster cases were added.
- Four new vector-leaf fixture cases requested strict_shape for leaf IDs, which
  upstream rejects (gbtree.h). Use the supported leaf-ID shape; production unchanged.
- Final v5 validates the reference-cut change and reset-lock refactor too.
No tolerances were widened, skipped, or replaced to hide numerical failures.

Remaining scope
---------------
Ordinary/in-memory matrices still use typed GPU indices and eager host mirrors.
Compressed disk-cache representation/internal ELLPACK save/load, optional
Snappy/nvcomp compression, native Apple GPU
array/half input, general metadata/state ownership and GPU collectives remain.
Small cut/shape metadata and existing tree orchestration stay on host. CPU batch
access intentionally materializes that page; approximate SHAP intentionally uses CPU.
This is no whole-process memory, speedup, NVIDIA-equivalence or cross-Apple claim.
