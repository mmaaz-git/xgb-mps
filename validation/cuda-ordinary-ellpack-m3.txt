Direct raw CSR compression for ordinary in-memory Metal matrices
===============================================================
Machine: Apple M3 Air, 8 CPU / 10 GPU cores, 16 GB unified memory.
Date: 2026-11-04. Coverage/ownership work; no new benchmark.

Implementation and CUDA contract
--------------------------------
SimpleDMatrix MPS generation now uses CUDA-derived SketchOnDMatrix with optional
Hessians/weights, host maximum row width, and direct compressed raw CSR writes.
Authority: ellpack_page.cu EllpackPageImpl(DMatrix*), CreateHistIndices and
CompressBinEllpackKernel; ellpack_page.cuh GetRowStride intentionally uses host
row pointers. Raw CSR remains in the ordinary matrix, matching upstream storage.

CompressedPage::PushCSR appends complete raw pages using bounded row windows.
The GPU kernel handles dense, feature-relative sparse and global-bin sparse
layouts; relative sparse slots use feature lower_bound, numeric values use upper
bound, categories use AsCat/lower_bound, all clamp to the final cut and null slots
are written. Nonzero input entry offsets, appended page rows and subwindows are
accounted separately. Zero-stride pages require zero input entries and no dispatch.
CUDA's total-memory/(16*stride*sizeof(Entry)) row budget is mapped to Apple's
recommended working-set budget and maximum buffer length. An internal window_rows
argument may reduce the automatic window for diagnostics; it cannot enlarge it.
Actual final compressed nnz is counted on GPU and checked against matrix metadata.

Generation creates a GPU view without host rows/bins/hits/columns or a typed GPU
index/transpose. Separate CPU/GPU views are published under a mutex. Explicit CPU
batch access materializes once and retains its compressed view. Approx pages with
NaN sparse threshold skip column initialization, matching the existing ordinary
GHist constructor. Empty/fixed requests keep cuts; mutable backend/maxbin/threshold
changes and explicit regen build a new generation. Retained batches keep old data.
Constant-Hessian approx reuses cuts; variable-Hessian approx rebuilds each updater
invocation. CPU-origin fixed-cut MPS conversion uploads bins once; mutable MPS
training instead constructs CUDA-derived cuts and compresses raw CSR.

BatchParam::for_cuts explicitly identifies cut-export/reference requests, and
MakeCache clears it. SimpleDMatrix returns existing metadata without conversion,
even when its initialization context is CPU and active cuts are MPS-generated.
Other batch consumers retain explicit CPU/GPU selection. Fixed-reference parameter
errors are preserved. Raw get_data and ordinary CPU prediction use original CSR,
so they do not request quantized host mirrors.

Statistics appended: ellpack_csr_dispatches, ellpack_csr_values,
ellpack_csr_input_bytes (completed commands; row+entry upload bytes, excluding cuts).
CPU-only reporting is zero. All native callers are rebuilt for the changed ABI.
Other new code does not change histogram/split/sketch arithmetic or tolerances.

Failures investigated
----------------------
Production build, focused raw-format/native-matrix runs and the 303-case existing
regression passed initially. New fixture corrections were source-driven:
- Initially expected three approx generations for squared error. Both the existing
  MPS updater and CUDA use !task.const_hess; constant-Hessian tests now require one
  generation. Added pseudo-Huber cases explicitly require three generations.
- Approx-to-hist QuantileDMatrix references fail the existing sparse-threshold
  mismatch check in SimpleDMatrix (also present in CUDA Ellpack batching). Tests
  preserve that error and verify metadata access itself remains without conversion.
- Approximate vector SHAP is unsupported in upstream shap.cc; test the explicit
  error, while keeping all supported exact vector SHAP checks.
- Reloaded vector models must keep their serialized three-target intercept rather
  than overwrite it with the training fixture's scalar .5. Reload now sets only
  device/nthread; prediction equality checks are unchanged.
- Upstream gbtree.cc rejects vector-leaf approx before construction. The public
  grid now covers supported vector hist, with scalar/multiple-target approx already
  covered in the existing regression. No unsupported API was invented for tests.
No numerical tolerance was widened or numerical comparison removed to hide a bug.

Remaining scope
----------------
Disk-backed SparsePageDMatrix and ExtMemQuantileDMatrix(on_host=False) still use
host gradient-index caches. Compressed disk representation/internal ELLPACK
save/load, optional Snappy/nvcomp compression, native Apple GPU arrays/half input,
general metadata/state ownership, remaining CUDA algorithm audits and distributed
GPU collectives remain open. Small metadata, raw ordinary CSR, source host row
width loops and host orchestration are intentionally retained. No speedup,
whole-process memory, NVIDIA-equivalence or cross-Apple claim is made.
