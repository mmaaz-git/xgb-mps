Changes:
  Preserve source NaN result when a finite query weight's FP32 square overflows.
  Removed MPS's CPU-specific CHECK_LE on raw sums; shared finalizer retains its
  non-NaN score check and warning behavior after collective aggregation.
  NaN squared weights yield score0/valid1 for query length>=3, matching CUDA's
  scanned_weight>0 branch. Infinite squares yield NaN/valid1. Public metadata
  validation remains unchanged; nonfinite/negative inputs are private API checks.
  Zero/underflowed squares retain score0/valid1. Short queries retain score0/valid0.
  No ABI/statistics layout changes, no new kernel or extra command/staging.

Algorithm correspondence:
  CUDA stably sorts descending labels, including equal-label pairs in input order.
  FP32 prediction differences become1/.5/0; NaN difference (including same-sign
  infinity subtraction) becomes0. Query weight square and score*square roundFP32.
  Pair terms/weights scan inFP64; positive final weight divides, otherwise score0.
  Existing Metal merge counting exactly counts wins/ties using ordered FP32 keys,
  retaining NaN/Inf exclusions, signed zeros and subnormal distinctions.
  For finite square w, numerator=wins*w+ties*float(.5f*w), denominator=pairs*w,
  followed byFP64 division. This changes addition association versus CUDA's
  quadratic scan; tested tolerance remains2e-12, no bitwise CUB/NVIDIA claim.
  CUDA's current launch checks total pairs<INT32_MAX. Metal's million-row analytic
  tests exceed that source limit and validate an extension, not CUDA execution.
  Empty/one-row slots are zeroed safely. CUDA's size-only TemporaryArray<double>
  is uninitialized; those slots get no writes when no pairs are generated.
  A mixed batch can reduce unwritten slots. Undefined behavior is not reproduced.
