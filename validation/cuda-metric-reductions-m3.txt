Implementation
--------------
Generic metric row loss and loss*weight round in FP32, then convert to binary64
PackedReduceResult fields, as CUDA does. CUDA source expressions are retained,
including gamma-nloglik's reciprocal/log expression instead of y/p+log(p),
std::max/NaN behavior, Tweedie exp/log order and pseudo-Huber operation order.
FP32 add/multiply helpers preserve subnormals; divisions use rounded software
binary64. No NVCC contraction behavior or actual libdevice output is asserted.

Scalar/multiclass, quantile/expectile and survival paths now finish sums using
recursive 256-input binary64 pair reductions entirely on GPU. The old generic
scaled-FP32 block sums and CPU scale restoration are removed, as are the host
partial-sum loops in quantile/expectile and survival metrics. Existing exact
integer reduction acceleration is used only when exponent-span checks prove
every subset sum exactly representable in binary64. Other blocks use software
binary64. CUB's hardware/toolkit-dependent association is not replicated.

The final reduction returns exactly 16 bytes (residue, weight) for each successful
nonempty call. The generic metric path also reads a separate 4-byte validation
flag. Final ratios remain host as in CUDA. Omitted GlobalSum call sites in the
MPS scalar, pseudo-Huber, quantile and expectile branches are restored. This is
shared collective integration, not new distributed Apple GPU transport.
New statistics: metric_reduction_passes, metric_final_readback_bytes and
metric_label_dispatches; CPU-only metal_info reports zeros. Previously missing
CPU-only zero keys for ranking_plan_* are supplied too. Internal Statistics ABI
changed; full validation rebuilds all native test executables.

Multiclass validation runs on GPU, after truncating labels to signed int as CUDA
does. Valid negative fractions above -1 therefore map to zero. Nonfinite or
out-of-int32 casts have no defined CUDA-source contract; they are explicitly
rejected. Atomic error bits replace CUDA's racing writes of an offending label;
error text reports the domain, not an arbitrary winning thread's label value.
Multiclass logloss follows prediction>epsilon (false for NaN); merror retains
first-index ties and ordered comparisons, including subnormal scores.

Math helpers
------------
The existing software binary64 Log/Exp are rounded to FP32. Log1p compensates
the low term of 1+x, including subnormal x. Sqrt refines a native seed in
binary64, scales positive subnormal seeds, preserves signed zero, and explicitly
rejects negative subnormals rather than letting native sqrt flush them to -0.
Gamma uses a Taylor series near 1 and 2, recurrence plus Stirling elsewhere, and
binary64 sine/reflection for negative nonintegers. Coefficients are ordinary
Euler/zeta, Bernoulli/Stirling and reciprocal-factorial mathematical constants;
no external implementation was copied. Gamma has exact +0 at one and two, +Inf at nonpositive integer poles and either infinity, and NaN for NaN.

Checked primary CUDA documentation:
  https://docs.nvidia.com/cuda/cuda-math-api/cuda_math_api/group__CUDA__MATH__SINGLE.html
  https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/mathematical-functions.html
The latter gives function-specific libdevice accuracy (including larger lgammaf
error in a negative interval). Our sampled checks do not prove a universal ULP
bound or bitwise equivalence with NVIDIA's different approximations.

New validation
--------------
tests/cuda_metric_reference.h uses explicit FP32 stores/operation boundaries,
host binary64 log/log1p/exp/sqrt/lgamma rounded to FP32, and independent scalar
source expressions. tests/metal_metric_api.mm compiles the production shader
with small diagnostics calling its actual row helpers, then separately checks
production MetricSums/QuantileMetricSums/SurvivalMetricSums and counters.

  100,057 math inputs / 500,285 fields: all match the binary64-libm FP32 oracle
  exactly (NaNs by classification), maximum observed ULP 0 for all five helpers.
  Test limits are 1 ULP for log/log1p/exp, 0 sqrt, 6 lgamma. Includes full-bit
  random floats, subnormals, infinities, signed zero, NaNs, poles, neighbors of
  transition points and dense exp-domain samples. These limits are a test budget,
  not a proof over every input and not NVIDIA execution comparison.

  349 production cases / 15,628,618 FP32 row-result fields, all exact versus
  the host source-formula oracle. Covers all 13 generic scalar/multiclass kinds,
  quantile and expectile, three target/seven-level layouts, integer-cast labels,
  signed cancellation, tiny/zero/large weights, full-bit random row values,
  NaNs/infinities, FP32 overflow, source clamps, and subnormal residuals/alphas.
  Includes 1/257/4,097/65,537-row inputs and an additional 262,145-row case.

  Production reductions compare actual GPU row terms with independent
  compensated sums. Finite error budget: 32*epsilon<double>*sum(abs(terms)).
  Maximum observed error/bound: 0.0373374008. Nonfinite outputs check
  classification and sign of infinity. Counter checks verify recursive GPU
  levels and exactly 16 bytes of readback, independent of row count.

  Included survival checks: 24 analytic 65,537-row raw-sum cases, three
  distributions, accuracy/likelihood, weights 0/1e-40/1/1e37. Weight sums exact;
  likelihood sums within 2e-14 relative. Two final GPU reduction levels and
  16-byte readback required. AFT gradients/CPU correction policy are unchanged.

  Twelve invalid-class direct calls verify GPU validation even when rejected.
  Empty calls return zero without dispatch. Eight new public Python cases cover
  fractional class labels and invalid labels. Existing scalar/multiclass and
  quantile tests now assert GPU final reduction and readback counters, retaining
  every existing numerical tolerance.

performance improvement or NVIDIA/cross-Apple validation is claimed.
