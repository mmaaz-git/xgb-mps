Authority and implementation
----------------------------
common/host_device_vector.cu: host/device access transitions, device selection,
constructor/fill/copy/resize/extend branches. common/device_vector.cuh gives
uninitialized GPU Resize(n), explicit-value initialization and retained capacity.
data/data.cu::SliceMetaInfo gathers matrix rows and scalar fields on device;
data/metainfo.cu::CheckFeatureTypes compares device arrays. Shared data.cc and
linalg.h define metadata Copy/Extend and tensor stacking.

An explicit DeviceOrd::MPS storage ordinal is added. The optional Metal vector
implementation owns shared Metal buffers and lazy std::vector mirrors. It tracks
host-writable/both-readable/device-writable access as CUDA does. GPU fills repeat
raw POD bytes, preserving float bits and struct payloads without arithmetic;
GPU blits copy and preserve growth prefixes. Shrink/regrow retains capacity.
Move ownership, host/initializer-list copies, device changes, self copy/extend,
empty arrays and bounds/overflow checks are covered. CPU-only builds keep their
original vector implementation. Metal buffers/commands remain synchronous.

Native float metadata now imports directly into these device allocations. Public
getters obtain host mirrors explicitly; repeated getters do not recopy. Matching
shape replacement reuses the allocation and invalidates the old host mirror.
MetaInfo::Copy/Extend and linalg::Stack preserve GPU storage when selected. GPU
row gather handles internal labels/margins/bounds/weights and feature-type
equality uses a device byte comparison. Invalid row IDs are rejected before
reading out of range. Group boundaries remain host vectors upstream and here.

The public SimpleDMatrix::Slice deliberately forces CPU upstream, even on CUDA.
It remains CPU here. External-memory slicing remains unsupported. Mixed host/GPU
metadata batches and self-extension have defined safe behavior; invalid memory
access implied by upstream self-extension or unchecked gathers is not reproduced.

This is not complete end-to-end GPU state ownership. The hybrid execution context
still returns CPU as its default generic storage device. Native metadata selects
MPS storage explicitly; many existing consumers still request HostSpan/HostView.
Those accesses can materialize/read back host mirrors. Other training/gradient/
prediction/model state and persistent dictionary ownership still need migration.
Metal addressable device spans are not MTLBuffer handles or DLPack descriptors.
Generic foreign writers must complete before passing allocations back.

Fourteen appended Statistics fields count vector allocation/live capacity,
copies/fills, import/readback/fallback bytes and GPU time, plus metadata gather
commands/values and feature-type equality. Live capacity excludes temporary
buffers and is not whole-process/peak memory. CPU-only values are zero. Every
native statistics caller is rebuilt for the extended ABI.
