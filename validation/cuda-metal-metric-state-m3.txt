Authority/scope
---------------
CUDA metric/elementwise_metric.cu, multiclass_metric.cu and survival_metric.cu
run row expressions/reductions on GPU and return a two-double host result for
collective/finalization. Metal now preserves explicit device input spans in the
actual scalar/multiclass, quantile/expectile and AFT/interval-accuracy evaluators.
Eager CPU device/view requests occur only after the Metal branch. Lower wrappers
use guarded shared bindings with offsets, retaining counted fallback uploads
for read-only/unshareable host views. The survival metric encoder uses the new
metric bindings while its objective branch remains unchanged.
No numerical shaders, reduction trees, cast boundaries or final scalar/collective
placement changed. Commands synchronous. Inputs remain unmodified.

The quantile/expectile Metal branches previously bypassed CheckRowWeights in the
shared CPU/CUDA reducer. They now apply the same check before dispatch. A query
weight for every one-row query must be rejected even when array length matches
row count. Existing empty-worker and zero-aggregate-weight semantics retained.
Two native Statistics fields appended: metric_shared_input_bytes and
metric_host_input_bytes, also public JSON and zero-valued CPU stubs. They count
binding/fallback bytes for these scalar metric families, not AUC/ranking inputs
or whole-program traffic. Final small returns remain in existing readback stats.
All native clients rebuilt for the enlarged statistics structure.
