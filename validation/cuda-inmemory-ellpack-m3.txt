Implementation and source contract
----------------------------------
IterativeDMatrix::InitFromMPS now creates one full compressed page, writes each
adapter batch directly into a temporary GPU page, and copies it into the full
page. This follows iterative_dmatrix.cu::InitFromCUDA's per-batch ELLPACK and
concatenation. Existing batch/row/column/nnz checks, single-batch metadata move,
weights/categories and iterator reset remain. EndAdapter rejects increased row
width. Actual final compressed nnz is checked on GPU before publishing the view.
Construction allocates no host row pointers, typed bins, hit counts or columns.
Small cuts, shape and other metadata remain host-owned.

CPU-origin quantile matrices compress their existing GHist bins on first MPS
access. Host maximum row-width calculation matches the CPU row loop in
ellpack_page.cu::EllpackPageImpl(GHistIndexMatrix). Rows/bins upload exactly once
for GPU packing; direct MPS construction does not upload host quantized bins.
Zero-stride inputs need no pack upload. No raw callback is revisited for conversion.

IterativeDMatrix retains separate CPU and immutable compressed GPU batch views.
A mutex serializes first conversion/publication and PageExists inspection. Host
materialization builds a fresh representation, fills rows/bins/hits/columns, and
publishes only after completion. GPU views never acquire host arrays, even when
other readers request CPU data. Shared batch references retain buffers after the
matrix is destroyed. Repeated CPU/MPS access reuses both representations.

Reference-cut lookup uses the owner's representation when either matrix uses MPS,
so CPU children do not materialize an MPS reference and MPS children do not pack a
CPU reference just for metadata. In-memory sparse export/get_data explicitly asks
for CPU batches when its context is MPS. Other device contexts are preserved.
Internal ELLPACK save/load remains separate and unported; public QDM.save_binary
was not added. No new kernel, numerical expression, statistic field or tolerance.

Remaining scope
---------------

representation/internal ELLPACK save/load, optional Snappy/nvcomp compression,
native Apple GPU arrays/half input, general metadata/state ownership, remaining
CUDA algorithm audits and distributed GPU collectives remain open. CPU-only
algorithms such as approximate SHAP intentionally use CPU. This checkpoint makes
no whole-process memory, speedup, NVIDIA-equivalence or cross-Apple claim.
