Compressed Metal disk caches and internal ELLPACK save/load
=========================================================
Machine: Apple M3 Air, 8 CPU / 10 GPU cores, 16 GB unified memory.
Date: 2026-11-04. Coverage/correctness work; no new benchmark.

Implementation authority
------------------------
Vendored CUDA ellpack_page_raw_format.cu Read/Write: aligned rows, bool dense,
stride, u64 byte count + compressed payload, base row, symbol count. Shared cuts
are separate. common/io.h supplies eight-byte field/payload alignment. The bit
writer uses eight-byte leading padding; actual allocation bytes are preserved.
SparsePageDMatrix::GetEllpackBatches supplies raw-CSR construction/regeneration;
IterativeDMatrix::Save/Load supplies the internal cuts + page-only contract.

Production IO exports compressed head/tail bytes through an owned shared staging
buffer, never CPU bins or diagnostic Readback. Read validates header geometry,
supported buffer size, overflow and truncation before publishing a compressed
view. prefetch_copy false retains an owned shared copy, true adds a private blit.
Neither aliases a soon-to-close mapping; both survive reader/cache destruction.
This is explicitly a copy fallback, not zero-copy mapped-file support. Internal
payload symbols are trusted, as in upstream raw cache handling.

MetalDiskPageSource integrates the existing aligned cache writer/readers and
bounded prefetch. Workers always create GPU-only views; explicit CPU consumers
materialize host arrays on the iterator thread. Metadata for_cuts avoids mirrors.
MPS ExtMemQDM disk construction writes one compressed adapter page per callback
batch to .metal-ellpack.page. Ordinary MPS external training compresses raw CSR
into the .gradient_index.page generation; CPU retains its original format.
Old source ownership is released before overwrite; retained GPU pages own bytes.
Matrix max_bin/device/Hessian regeneration and raw-row cache ownership remain.

Internal QDM Save/Load serializes CUDA's actual cuts fields and compressed page;
minimum cut values, labels/weights/general MetaInfo and training parameters are
not in the upstream format. Loaded pages can be inspected/re-saved on GPU; CPU
materialization rejects missing training parameters. No public save_binary API.
CPU-origin QDM must acquire a compressed Metal page before internal save.

Statistics append ellpack_io_read_pages/write_pages/read_bytes/write_bytes/
dispatches. Bytes count compressed payload, not headers/cuts. GPU blit timing
contributes to ellpack_gpu_time_ns. CPU-only counters remain zero. All native
executables are rebuilt for the modified Statistics/Page ABI.

Limits and next work
--------------------
Ordinary external on_host=True still uses the disk source. CPU-origin fixed
external matrices retain their compatibility path; upstream CUDA rejects CPU-origin
external QDM GPU access, so new compressed conversion is not a parity requirement.
Mapped-file zero-copy,
optional Snappy compression, native Apple arrays/half, generic metadata/state,
remaining CUDA algorithm audits and collectives remain open. Local independent
source/CPU checks are not measured NVIDIA equivalence. No cross-Apple execution,
new speedup or whole-process memory measurement is claimed.
