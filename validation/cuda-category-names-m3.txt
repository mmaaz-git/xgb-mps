CUDA-source typed category names and recoding maps
2026-11-04; Apple M3 / 10 GPU cores / 16 GB unified memory

Scope and source authority
--------------------------
Ported name-index initialization/sorting, whole-dictionary type/empty validation,
segmented lower-bound lookup, exact candidate equality and first-missing search.
Source: xgboost/src/encoder/ordinal.cuh::SortNames/Recode and segmented search
operators; data/cat_container.cu::Sort/MakeCatAccessor; ordinal.h::BasicChecks,
ReportMissing and the category type list. String ordering comes from the signed
int8 spans and xgboost/span.h::LexicographicalCompare.

This is not the complete categorical preprocessing port. Dictionary ownership,
model category copies, packing/staging and row-level map application remain host.
No benchmark or NVIDIA execution comparison was run.

Implementation
--------------
metal_category.h exposes SortCategories and RecodeCategories for host views.
A packed descriptor records payload/offset byte locations, feature segment,
size, explicit integer/string type and the source empty flag. Payload bytes keep
all integer widths; there is no float/double conversion of names. String offsets
and values preserve embedded NULs and signed byte comparisons.

Sort creates (feature, local-index) keys on GPU, merges by feature then name,
and extracts local indices on GPU. Merge ranks choose stable ties. CUDA uses
thrust::sort, so duplicate-name tie order is not promised equivalent. Public
category dictionaries have unique names; valid unique-name results match the
source order exactly. The original numeric/string category data is not sorted
or rewritten on the host.

Recode uses source host BasicChecks, then GPU global type/empty validation,
per-name lower_bound and exact equality, mapping into original local indices.
A GPU atomic minimum selects the first missing incoming index. Error strings
are formatted on the host, as in CUDA. In particular, any schema mismatch wins
before all missing-name errors: the CPU implementation instead checks each
feature and could report an earlier missing name before a later type mismatch.
The test suite explicitly distinguishes that source behavior.
Successful maps return to host accessors. Failed maps are not copied to host.

Production integration:
- CatContainer::Sort with an MPS context routes model category sorting to Metal.
- cpu_impl::MakeCatAccessor routes MPS name recoding to Metal before supplying the
  existing mapping view. This covers batch/in-place/leaf prediction and SHAP.
- MPS still uses CPU DeviceOrd for storage; IsMPS is checked before CPU fallback.
- CUDA+Metal combined builds are already rejected by CMake, so the non-CUDA
  CatContainer implementation is the appropriate Metal integration point.
- CPU-only behavior and CUDA sources are unchanged.

Statistics ABI gained category_sort_dispatches, category_recode_dispatches and
category_gpu_time_ns. They count completed whole commands, not individual passes.
No-category sorting/zero-feature recoding dispatch nothing. Nonzero-feature
recoding still validates schemas when all category counts are zero. GPU schema
or missing-name failures count completed work. The duration excludes host packing,
copying and applying the mapping to rows. CPU-only builds expose zero values.

Remaining limits
----------------
No measured NVIDIA/libdevice or cross-Apple equivalence. Duplicate category-name
tie order is not specified by CUDA's sort. The public adapter's signed-range
restriction on uint64 names is preserved. No float category-name support was
added: the vendored encoder supports only integer/string names.
Dictionary arrays/maps are staged and read back, and row accessors still apply
maps while filling host chunks for prediction/SHAP. Device dictionary caches,
GPU category copy/storage, row preprocessing, general metadata validation and
Apple array interoperability remain separate work. No new performance claim.
