Ordinary external-memory Metal host caches
=========================================
Machine: Apple M3 Air, 8 CPU / 10 GPU cores, 16 GB unified memory.
Date: 2026-11-04. Coverage/correctness work; no new benchmark.

Implementation authority
------------------------
Vendored sparse_page_dmatrix.cu::GetEllpackBatches selects EllpackHostPtr when
on_host is true. CalcCacheMapping uses is_validation=true, one page per input
batch, default host ratio one for multiple pages, overridden to zero for a single
page. Explicit ordinary cache_host_ratio is rejected upstream. C API callback
construction defaults min_cache_page_bytes to MatchingPageBytes() (zero), rejecting
other values because ordinary page concatenation is unsupported. Metal preserves
these rules and maps host/private buffers to Apple unified-memory storage modes.

MetalPageSource gains a constructor for raw-CSR generations plus Append/Finalize.
It counts actual compressed non-missing symbols, commits each page's storage,
retains it, commits byte offsets and starts existing bounded prefetch. The raw
CSR file remains. No quantized disk file is written by host-mode MPS generation.
Compressed page reading, CPU-only materialization and metadata-only behavior use
the already validated reader policy. No new GPU shader or numerical formula.

SparsePageDMatrix tracks its active host/disk source before deciding cache reuse.
Empty/fixed/metadata requests retain active storage. Mutable backend/max-bin/
approx regeneration releases prior ownership and chooses the host .metal-ellpack
(non-file) cache entry or disk .gradient_index entry. CPU-generated disk files may
remain until matrix destruction; host regeneration doesn't write those files.
Retained GPU views own their buffers across source replacement and destruction.
CPU construction keeps its original disk behavior with either on_host setting.

Scope
-----
Host/disk selection for ordinary external matrices is now implemented. Mapped-file
zero-copy, optional Snappy compression, native Apple arrays/half, generic device
state/metadata, remaining CUDA algorithm audits and collectives remain open.
CPU-origin external quantile compatibility is retained; CUDA rejects GPU use of
CPU-created ExtMemQuantileDMatrix, so new conversion there isn't a parity requirement.
Local CPU/source checks do not establish measured NVIDIA or cross-Apple equivalence.
No whole-process memory or speedup claim.
