kDLMetal=8 data is an id<MTLBuffer>, not a host element pointer. The bridge imports
offsets and signed element strides. It validates metadata and bounds, copies the
addressed span by GPU blit into private owned storage, then feeds the existing
GPU sketch/compression and prediction-input pipelines. No feature payload is
converted to NumPy, CPU-staged or diagnostically read back in those paths.
Final quantile summaries/results retain the backend's existing host contracts.

Covered public paths: QuantileDMatrix, ExtMemQuantileDMatrix with host and disk
caches, DataIter batches, reference cuts and inplace prediction. DLPack input
infers MPS construction; explicit CPU construction rejects it. Host labels and
other metadata remain required. Inplace prediction returns NumPy.

Corrections during validation
-----------------------------
An initial run passed 71 Python cases and failed 12 iterator tests because the
test incorrectly set cache_host_ratio for disk caches and called set_param with
an unsupported keyword. Corrected tests passed all 12; no backend workaround.
Review moved producer completion to each import, including cached exports.
Capsule rename failure detaches consumer cleanup so ownership is not duplicated.

Without a coordinated OpenMP runtime, actual PyTorch+XGBoost training crashed.
The macOS crash stack alternated the wheel's bundled libomp and Homebrew libomp
internal barrier frames. Setting DYLD_LIBRARY_PATH=/opt/homebrew/opt/libomp/lib
before launch resolved this; threadpoolctl reported one Homebrew runtime and
both producer integrations passed. scripts/test.sh exports the same setup via
LIBOMP_ROOT (or brew --prefix libomp). No installed package was patched and
KMP_DUPLICATE_LIB_OK is not used. General mixed-runtime packaging remains open.

Scope limits
------------
Not full CUDA parity. Native ordinary DMatrix, labels/weights/base margins/groups,
custom gradients, GPU output tensors, sparse/columnar device adapters and general
device-owned state still require work. Foreign producers must finish writes;
the C API requires a valid handle and source lifetime through synchronous import.
BF16, complex, float128 and device IDs other than 0 are unsupported.
No NVIDIA execution, cross-Apple-device comparison or new benchmark performed.
