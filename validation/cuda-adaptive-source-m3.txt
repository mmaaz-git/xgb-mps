CUDA-source adaptive objectives and generic reduction precision
2026-11-04; Apple M3 / 10 GPU cores / 16 GB unified memory

Scope
-----
Absolute-error and quantile objective expressions, residual-scale statistics,
and common::Reduce now follow their CUDA source precision and control flow.
No performance benchmark was run. Full CUDA parity is still incomplete.

Authority and implementation
----------------------------
Vendored sources:
 xgboost/src/objective/regression_obj.cu (MeanAbsoluteError)
 xgboost/src/objective/quantile_obj.cu (QuantileRegression)
 xgboost/src/common/numeric.cu
 xgboost/src/common/optional_weight.cu and optional_weight.cc
 xgboost/src/common/device_helpers.cuh (dh::Reduce)

Important correction: numeric.cu returns double but supplies thrust::plus<float>
to dh::Reduce. Each addition is FP32. The final result is returned as double.
The double initial value does not override the explicitly float binary operator.
The inspected pinned CCCL accumulator type derives from the operator's result;
transparent cuda::std::plus with a double initial value instead yields double.
The latter is used by SumOptionalWeights. Default optional weights are computed
as n_samples * float(default_weight), also a float product before widening.

Metal common::Reduce now calls SumFloat32. It uses recursive 256-input GPU sums,
then returns the FP32 value as double. The generic API preserves dh::Reduce's
outer batch size INT32_MAX/2 (1,073,741,823), including FP32 host aggregation.
Optional-weight array sums retain the existing binary64 GPU reducer.
Absolute-error's initial explicit weight reduction consequently changes to FP32,
as required by its call to common::Reduce. No CPU execution was changed.

Adaptive scales now use FP32 root terms and FP32 sums; weights reduce separately
in binary64. Recursive GPU reduction produces targets+1 double statistics.
They pass through GlobalSum using a CPU context, as in CUDA, before GPU scale
application and gradient calculation. Empty workers participate, then return
without dispatching. The new empty setup initially retained a labels.size()/rows
division; code review caught and fixed it before API testing. Distributed MPS
Learner training remains rejected. These tests exercise objectives directly,
not distributed trees or GPU collective transport.

Absolute gradients retain hypotf(delta,residual), norm>0 ? delta/norm : 1,
(w*residual)*curvature and w*curvature. Hypot uses software binary64 squares and
Newton square root, then one FP32 rounding. Infinity dominates NaN, as in CUDA.
Quantile retains FP32 smoothing-scale multiplication/division, tanhf, continuous
ratio at zero, fmaxf curvature floor, source product order and early zero output.
Tanh uses binary64 exp/expm1-style evaluation before FP32 rounding, preserving
small and subnormal inputs. Every row's gradient remains on GPU.
No CPU correction path or new host per-row calculation was introduced.

Limits
------
Metal's FP32 tree has a different association from architecture-dependent CUB.
The generic multi-billion-element batch boundary has not been capacity-tested
on this 16-GB machine. Adaptive fused reductions use the full local-input tree;
inputs crossing CUDA's outer batch boundary remain an association-validation
limit. Default-weight count rounding above 2^24 follows the source cast, but
is not validated by a correspondingly large adaptive allocation in this suite.
The mathematical references establish source-expression/primitive behavior on
this Mac, not NVIDIA libdevice identity, compiler-contraction behavior or
cross-Apple equivalence. No new performance claim is made.
