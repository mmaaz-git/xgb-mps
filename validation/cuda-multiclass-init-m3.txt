Implementation and source-specific behavior
------------------------------------------
The multiclass initial histogram, normalization, logarithms and mean subtraction
now run on Metal. Generic vector normalization also covers quantile initialization.
SmallHistogram sorts ascending float labels with stable radix records, computes
run-start flags and exclusive integer prefixes, emits run boundaries, and sums
weights in FP32 per run. Every output bin is written, including zero tail bins
and empty inputs. Labels and weights remain unchanged. CUDA's ArgSort explicitly
passes is_overwrite_okay=false to CUB dispatch; inspected local CCCL source
confirms that this flag forbids overwriting input keys.

CUDA packs run sums rather than scattering by unique class labels. For example,
[1,1,3] with four bins produces [2,1,0,0], unlike CPU [0,2,0,1]. This difference is
preserved, documented and tested; it can change base scores with missing classes.
The earlier read-only next-task note incorrectly said fractional objective labels
were allowed. Reinspection found ValidateLabel's floor(y)==y predicate. The port
keeps this predicate and tests rejection BEFORE histogram dispatch. (Multiclass
METRICS still have a different integer-cast label policy, unchanged here.)

Low-level SmallHistogram rejects nonfinite labels or more distinct labels than
output bins via a GPU flag and guards every boundary write. Host outputs remain
unchanged on rejection. Excess runs would overflow CUDA's fixed-size unique/count
buffers, so no defined CUDA result is asserted for that case. Optional default
weights, strided inputs/outputs and signed-zero ties are supported. Empty labels
with nonempty bins zero those bins on GPU; wholly empty operations do not dispatch.

VectorArithmetic performs double multiplication followed by float narrowing for
VecScaMul; division retains source host double reciprocal then multiplication.
LogE rounds float(value+epsilon) before log; centering subtracts float operands.
Software float helpers preserve subnormals. Scale/div/sub results are checked
against explicit host source expressions; log permits one FP32 ULP relative to
host binary64 log rounded to FP32. Actual libdevice output is not asserted.

Production MeanKind::kFloat32 now uses FP32 terms AND accumulation, replacing
its prior binary64 reduction. Terms divide by float(row_count), and each of 256
lanes accumulates strided terms before a shared FP32 tree. Sample and weighted
sample means remain binary64. Old low-level mean kernels/tests remain, but
production float means dispatch the new kernel. This is an explicit precision
alignment, not a promise of CUB's hardware-dependent sum association.

Internal stats ABI appends small_histogram_dispatches, vector_arithmetic_dispatches,
float_mean_dispatches; the C API exposes them and CPU-only zeros. First two use
initialization_gpu_time_ns. Float means also increment existing mean_dispatches
and use mean_gpu_time_ns; these overlapping counters must not be added together.
All native binaries must be rebuilt after this ABI change.

Validation
----------
New tests/metal_linalg_api.cc calls public shared linalg functions with MPS context
and production Metal APIs; no test-only reimplementation replaces the kernels.
Independent stable host sorting and run grouping determine expected packed bins.
Integer/power-of-two cases require exact sums; other finite reductions compare
long-double sums with k*epsilon/(1-k*epsilon)*sum(abs(terms)), k=ceil(n/256)+8.
This is a bound for the selected parallel association, not a CUB bitwise oracle.
Overflow results and vector NaN/infinity behavior are checked separately.
A transparent cancellation
fixture distinguishes FP32 mean accumulation from the former binary64 result.

Corpus includes 0/1/257/4097/65537 rows, 1/3/33/257 bins, an additional
262145-row/1025-bin case, missing class IDs, sorted ties, zero/subnormal/large
weights, default weights and overflow. Vector tests use full-bit random floats,
subnormals, NaNs/infinities, signed zero and binary64 scalar extremes; strided
buffers verify untouched elements. Means include multiple strided targets and
outputs, cancellation, constant input and wide exponents. GPU counters required.
Invalid label/run counts must fail without modifying output. Empty no-op guards
also checked. A binary64-scalar witness count distinguishes double from float
scalar multiplication.

24 new public Python cases cover complete/missing/gapped class labels, optional
integer weights, source-derived base scores, CPU agreement where algorithms
agree, model reload, invalid fractional/range labels and zero/tiny weight errors.
Existing quantile tests now require one GPU vector normalization; their exact
CPU equality requirement is unchanged. Existing mean/public tolerances unchanged.

Remaining limits
----------------
CUB association, actual NVIDIA/libdevice execution and cross-Apple execution
remain unverified. Generic objective arithmetic still requires source audit;
metadata/category recoding, adapter/device-array sketches, matrix preprocessing,
generic allocation/state, device interoperability, distributed GPU collectives
and persistent/asynchronous ownership remain incomplete. Host scalar staging,
input/output copies and synchronization still occur around these new kernels.
No full CUDA parity or performance improvement is claimed.
