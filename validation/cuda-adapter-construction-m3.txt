CUDA adapter frontend and explicit Metal QuantileDMatrix construction
2026-11-04; Apple M3 / 10 GPU cores / 16 GB unified memory

Scope and API
-------------
QuantileDMatrix(..., device="mps") now selects GPU construction from host dense
and columnar arrays, including DataIter batches and reference matrices. C callers
use the optional device field in XGQuantileDMatrixCreateFromCallback JSON.
Default input-device inference is unchanged, including host-input CPU construction
in the sklearn wrapper. Booster device does not retroactively change construction.
CPU-only builds accept explicit CPU construction and reject MPS clearly.

This is the CUDA adapter computation path translated onto Metal with host-array
staging. It is not native Apple GPU tensor interoperability. Raw float16 interfaces,
sparse device adapters, external-memory adapter construction, generic GPU metadata,
collectives and persistent GPU ownership remain unfinished. Existing ordinary MPS
SparsePage-backed training is unchanged. No benchmark was run.

Source authority and behavior
-----------------------------
common/hist_util.cuh::AdapterDeviceSketch, ProcessSlidingWindow,
ProcessWeightedSlidingWindow and MakeEntriesFromAdapter; data/quantile_dmatrix.cu
MakeSketches; iterative_dmatrix.cu::InitFromCUDA; device_adapter.cuh::GetRowCounts
and encoded columnar access; common/quantile.cu::SketchContainer::Push;
ellpack_page.cu validation/bin construction and gradient_index.cu host conversion.

The CUDA frontend uses 2^26 raw logical slots, including missing entries, and may
split a row. The approximate pruning count is ceil(window_slots / num_features).
Metal preserves both the raw window extent and this count instead of windowing
only the compacted nonmissing entries. Full row maxima are computed even when a
boundary row contributes only part of its entries to a window.

SketchContainer::Push increments rows_seen before discovering an empty summary.
The existing low-level Metal sketch had returned early before that increment;
this is now corrected. The independent native oracle was updated from the same
source rule. All-missing windows affect subsequent pruning budgets. Empty calls
with zero approximate rows remain no-ops.

Training encoded-columnar values are recoded before IsValidFunctor, unlike the
prediction adapter loader which checks missing before mapping. The GPU kernel
preserves this distinction, with an independent finite-sentinel/category-map
fixture. Invalid-domain categorical casts retain the previously documented
missing/invalid-code preservation policy; actual NVIDIA cast behavior is unverified.

Infinity is counted/sketched as a valid element unless it equals the missing
sentinel. Numeric infinity is rejected at bin/page construction, matching CUDA's
NoInfInData phase. Invalid categorical cuts may fail during cut materialization,
also preceding page construction. There is no host feature-correction pass.

Implementation and remaining placement
--------------------------------------
common/metal_adapter.h exposes an opaque GPU AdapterInput window. PackedInput's
raw typed byte windows and descriptors are reused; new kernels count/scan rows,
compact Entry records in source order, and finalize global row offsets. Typed
conversion, masks, missing filtering and training category recoding execute on GPU.
The scan uses existing recursive uint64 prefixes. Counts/row maxima/status are
small host reads; compacted feature values and raw row-pointer arrays remain on
GPU for sketching/binning. A diagnostic Readback API is not used in production.

CudaSketch gains per-batch SetWeights and a resident AdapterInput overload. Its
existing sorting, weighted FP32 prefixes, category deduplication, pruning, merging
and rank repair consume GPU buffers directly. Group weights use the existing GPU
expansion, with per-callback metadata. Independent tests use exactly summable
weights so scan association does not obscure algorithm checks. General weighted
scans retain their declared Metal association; NVIDIA/CUB identity is unverified.
MakeCudaCuts factors the unchanged host cut-materialization logic for both callers.

IterativeDMatrix::InitFromMPS performs two callback passes:
1. GPU decode/count/compact plus resident sketches, with source geometry/category
   consistency checks and per-batch weights; or reference cut reuse.
2. GPU decoding and direct bin assignment, then GPU global row-offset calculation.
   Partial first rows preserve earlier row starts and update completed row ends.
   Changed row/nonmissing/batch counts are rejected.
The original CPU constructor remains selected by default. Array/columnar adapters
are supported; explicit MPS CSR construction reports its current limitation.

BinEntriesBuffer is factored from the existing binning implementation so the GPU
input no longer needs a feature-value readback/reupload. Quantized bins and global
row pointers still return to the existing host GHistIndexMatrix. Its host column
mirror is built from already-quantized bins for CPU interoperability, analogous
to CUDA's host gradient-index conversion. Metadata Extend, raw packing/uploads,
dictionaries, allocation and ownership remain host work. Commands synchronize.
This does not complete the device/storage backend or claim a performance gain.

Instrumentation
---------------
adapter_prepare_dispatches: completed count/scan commands and compaction commands
when nonmissing entries exist. adapter_index_dispatches: global row-offset output.
adapter_gpu_time_ns: device time for those operations, excluding packing, uploads,
waits, metadata and host column storage. Binning has its existing separate counter.
adapter_debug_readback_bytes: explicit raw-record/row-pointer diagnostic reads;
production tests require it unchanged. Quantized matrix output is not raw readback.
All four values are zero for CPU-only builds. Statistics ABI changed; all native
binaries must be rebuilt. scripts/test.sh registers the new native suite.
