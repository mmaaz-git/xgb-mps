GPU Snappy compute codec and external host-cache integration
===========================================================
Date: 2026-11-04
Host: Apple M3 MacBook Air, 8 CPU cores / 10 GPU cores / 16 GB unified memory.
Baseline: 9fd2e98 (ordinary external-memory host caches).

Scope and authority
-------------------
Vendored CUDA common/device_compression.cu/.cuh/.h and
 data/ellpack_page_source.cu define chunk metadata, coalescing, sparse selection,
 the optional compute fallback, default ratio 0.4, 2MiB chunks and forced prefetch.
Raw byte format: https://github.com/google/snappy/blob/main/format_description.txt
nvCOMP API: https://docs.nvidia.com/cuda/nvcomp/c_api.html#snappy

Metal encodes actual LZ77 backreferences and decodes all raw Snappy tags. CPU work
is metadata/length headers/status handling; payload encoding/decoding/coalescing
is GPU work. Hash/output scratch is bounded to one block with a per-block
Objective-C autorelease scope. Diagnostic host exchange is separately counted.
Production cache paths do not call the diagnostic codec or raw page readbacks.

External quantile host caches use the existing native
ExtMemConfig::SetParamsForTest(ratio, true) opt-in. CUDA IsDenseCompressed eligibility
excludes both dense and feature-relative sparse pages. Snappy operates on the
selected host middle segment, leaving a plain prefix and private suffix.
Logical offsets remain unchanged; HostStorageBytes counts actual cache payload.
View/Restore/NonMissing/Readback/Copy all reconstruct through the GPU codec.
Retained views own reconstructed buffers. Disk ELLPACK bytes stay unchanged.

No automatic/public Python compression option is added. Apple CUDA DE hardware
is not claimed. Ordinary external and disk cache selection stays unchanged.
Production libxgboost dependency inspection (otool -L) confirms no libsnappy link.
Google Snappy 1.2.1 is solely an independent test oracle.

Focused results
---------------
Initial codec: PASS 248 valid cases / 346 rejected inputs / 1,576 fields /
132,381,418 exact decoded bytes; 116 compression / 684 decompression dispatches.
- GPU encode -> Google CPU decode, Google CPU encode -> GPU decode.
- Empty, tiny, random, incompressible, repeated and mixed inputs; chunks through
  2MiB and partial chunks across 4MiB; smaller configured block sizes.
- Real compression on repeats (<10% of original bytes).
- Literal lengths in all forms, COPY1/2/4, COPY4 offset 70,000, overlap,
  valid non-minimal encodings, truncation, bounds, impossible references,
  varint overflow, declared-size mismatch, trailing bytes and invalid metadata.
- 400 deterministic mutations compare actual acceptance with Google decoding.
- Output guards checked on successful and failed GPU decode.

New integration cases include 96 ELLPACK cases, 32 GPU consumer cases and 120
external-cache cases. Independent CPU bit writers/quantizers check exact restored
symbols, rows, bins, hits and columns. Eligibility includes dense, relative-sparse,
sparse and all-missing data; zero/mixed/all host ratios and compression fractions,
default/disabled/native opt-in, both prefetch settings, interrupted CPU/MPS reads,
committed source copying, retained pages after destruction and physical payload
accounting. Six fits compare compressed versus plain Metal predictions, leaf IDs
and SHAP exactly; CPU predictions/SHAP of the fitted model use absolute tolerance
1e-5. Training asserts actual GPU decompression and no host materialization.

Final build additionally includes per-block autorelease scoping and two large

at nonzero destination offsets and compare every restored byte. Final native
ELLPACK result: PASS 355 cases / 11,637,190 exact bytes / 55,828,485 exact fields.

Limits
------
No new benchmark or speedup claim. Codec throughput and public selection are
future performance work. No NVIDIA execution or cross-Apple-GPU comparison.
Compressed bytes need not equal nvCOMP output; decoded bytes must match exactly.
This completes an optional codec path, not all CUDA coverage. Native Apple tensor
interoperability, general state/metadata, algorithm audits, GPU collectives and
mapped-file zero-copy remain tracked separately.
