Operation scope and authority
-----------------------------
Vendored data/simple_dmatrix.cu/.cuh: CopyToSparsePage, CountRowOffsets,
CopyDataToDMatrix. External CUDA iterators use sparse_page_source.cu::DevicePush.
Source defines typed float conversion, missing filtering, nonmissing infinity
rejection, row counts/prefix offsets, ordered sparse entry packing and one host
count read to size allocation. Existing Metal adapter kernels implement these
operations; ordinary construction now consumes them.

New XGDMatrixCreateFromMetal and Python DMatrix dispatch use native descriptors
and owned GPU source snapshots. Ordinary external DataIter ingestion uses the
same GPU sparse-page path. Two-dimensional zero-row/zero-column shapes retain
their dimensions. This removes the old bridge's positive-column restriction.
Scalar/vector feature inputs still reject; metadata/gradients have separate rules.

Output CSR offsets and entries are GPU-blitted into guarded shared SparsePage
allocations where eligible; a counted host payload-copy fallback handles other
allocations. Nonmissing infinities reject before resizing/publishing the output.
Missing infinity, signed zeros and subnormals follow the input predicates.
Source buffers may be private, strided and released/overwritten after snapshot.
No producer tensor payload is converted through NumPy or diagnostic Readback.

Raw-CSR sketch and compressed ELLPACK consumers now bind safe shared spans at
the actual buffer byte offset, otherwise use counted uploads. Borrowed views are
synchronous and never cached. Source ownership covers the command and buffer
lifetimes. Host get_data, save/load, slice and CPU training/prediction remain
available; this does not add generic private-GPU SparsePage ownership. External
raw row-page disk serialization and both existing compressed cache modes remain.

CPU tree inplace prediction from native Metal inputs now takes the existing
ordinary-matrix fallback, including base margins and iteration ranges. The MPS
marker is checked separately from the generic CPU storage device ordinal. Normal
MPS inplace prediction still uses the GPU tensor path directly.

Counters: tensor_csr_dispatches, tensor_csr_values,
tensor_csr_shared_output_bytes, tensor_csr_host_copy_bytes, tensor_csr_gpu_time_ns.
These measure completed output publication and entry counts; adapter_* retains
filter/count/prefix/scatter activity, and tensor_* retains source snapshots.
csr_shared_input_bytes / csr_input_copy_bytes count raw-CSR sketch/compression
span access, including repeated pointers across windows. ellpack_csr_input_bytes
remains logical input extent rather than physical transfer bytes. All native
statistics callers require rebuilding. CPU-only fields remain zero.

Remaining scope and correction from upstream audit
-------------------------------------------------
Native columnar input with masks/dictionaries, GPU outputs, general metadata/
state manipulation and ownership, remaining CUDA arithmetic audits, GPU
collectives and cross-hardware validation remain open.
Native CSR/CSC device-array inputs are not a CUDA parity requirement: upstream
python-package/xgboost/data.py::dispatch_data_backend explicitly rejects cupyx
CSR/CSC, and data/proxy_dmatrix.cc::SetCsr requires on_host. A Metal-specific
sparse binding would extend upstream capability. Host sparse input and internal
GPU sparse operations remain in scope; this correction does not remove them.
No new benchmark or NVIDIA/cross-Apple-device execution in this step.
